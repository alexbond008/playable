How it works

From a static PDF to a game that tells the truth

One command. The agent reads everything you give it, proves the physics against your answer sheet, then builds the game from a hand-crafted kit.

01

Read the source

PDFs, docx, slides, spreadsheets, code, Simulink models and whole lab folders. Answers become test cases; your own answers become claims to check.

02

Pass the truth gate

The model must reproduce every official answer. Code is compiled and run for real.

{{TRUTH_SAMPLE}}
03

Build and playtest

A single offline HTML file. A bot plays every level on desktop and phone, drags every control, and checks the frame budget before you see it.

What makes it different

The game is the lesson

Learning science, built in

Predict first and say how sure you are. Discover the relationship with your hands. The equation unlocks as a power-up you use in later levels. Recall questions come back days later.

It's true

Every number is reproduced from your source, and every claim about code is checked with a real compiler. When the answer sheet and the physics disagree, the game says so.

It feels like a machine

Real objects on a workbench, a physics engine, sound that follows the physics, haptic detents, and three looks: Bench, Cyanotype and Paper.

Limits

What it is and isn't

  • It teaches what is in your material and checks it against your answers. It does not replace doing the problems.
  • Building a game takes a while; you get an ETA up front. Playing it is instant and works offline.
  • The parts library starts with electrical, mechanical, control and embedded systems. New domains grow the kit.
  • Platform-dependent facts (for example the size of std::string) are stated with the platform they were measured on.
